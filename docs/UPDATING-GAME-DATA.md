# Updating exported game data

Everything under `static/data` is generated by the D2R Multi-Export tool
([D2R-Reimagined/d2r-multi-export-tool](https://github.com/D2R-Reimagined/d2r-multi-export-tool)):
`keyed/`, `strings/`, `sprites/`, `extras/` and `manifest.json`. Never edit these files by hand,
including to fix presentation or link compatibility; change the mod, the exporter or the website
code and export again instead.

The website has no installation, publishing or verification step of its own. Server loaders
import and the browser fetches the files in `static/data` exactly as the exporter writes them.

## Workflow

1. In the exporter, set the **Mod Data Directory** and, optionally, the **CASC Data Directory**.
2. Select this checkout's existing `static/data` directory as the **Output Files Directory**.
3. Run the normal **Import and Export** action. From the command line, in the exporter checkout:

   ```powershell
   dotnet run --project .\D2RMultiExport.Console -- export `
     --mod-data "..\d2r-reimagined-mod" --casc-data "<path-to-CascView-extraction>" `
     --out "..\d2r-reimagined-website\static\data"
   ```

4. Review the changes with `git status` and `git diff`, and check `extras/import-report.txt`.
5. Commit and push the website changes, keeping `static/data` changes in their own commit,
   separate from code changes.

## Export modes

A **normal export** (the default) writes directly into `static/data`. It overwrites files with
matching paths, creates new files and leaves every other existing file untouched. Files from an
earlier export that the current export no longer produces therefore stay behind; look for them in
`git status` and remove them deliberately, or use a destructive export.

**Destructive export** (the exporter's "Destructive export — replace all existing destination
contents" checkbox, or `--destructive`) is optional and off by default. The run is generated in a
hidden `.d2r-export-new-*` directory inside `static/data`. Only if the run records no errors are
all previous contents of `static/data` replaced, including obsolete files; warnings do not block
the replacement. A failed or aborted run keeps the previous contents. The exporter refuses a
destructive export into unsafe locations such as a drive root, a Git repository root or a
directory containing the mod or CASC sources; `static/data` itself is accepted. A destructive run
killed mid-replacement can leave hidden `.d2r-export-new-*` or `.d2r-export-old-*` directories
behind. They are ignored by Git; the next successful destructive export removes them. See
"Export modes" in the exporter's `README.md` for the full rules.

## Manifest and reports

`manifest.json` is written last. It records whether the run succeeded and was complete, each
export step's status and every file the run wrote, with its byte size and SHA-256. It describes
only the current run: after a normal export, `static/data` can still contain files the manifest
does not list, such as outputs of earlier runs or of steps that were skipped this time. Only a
successful destructive export guarantees that the directory contains exactly the manifest's
files. The website does not read or verify the manifest.

`extras/` holds the exporter's text reports, including `import-report.txt`,
`source-report.txt` (which source supplied each file), `casc-fallback-report.txt`,
`asset-report.txt` and `missing-translations.txt`. Use them to review an export; the website
does not depend on them.

## Cube recipe links

Build guides store cube-recipe references as `[[item:cube-recipes:<key>]]`. Guides saved before
recipes had stable identities use the recipe's row number (`Index`) as the key, and row numbers
change whenever an export inserts a recipe. Every exported recipe now carries a stable exporter
`Id`, and new references store that `Id`.

`src/lib/data/cube-recipe-aliases.json` maps the old row-number keys to recipe `Id`s, so
existing guides keep resolving through `src/lib/cube-recipe-ids.ts`. It is frozen compatibility
data, not part of the export, and does not need updating after future exports. Do not edit
exported recipe JSON or recipe identities to keep links working.
