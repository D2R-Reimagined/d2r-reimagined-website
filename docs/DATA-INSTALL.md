# Updating exported game data

Everything under `static/data` is generated by the D2R Multi-Export tool: `keyed/`,
`strings/`, `sprites/`, `extras/` and `manifest.json`. The manifest lists every file the
export generated with its byte size and SHA-256. Never edit these files by hand; export again
instead.

The website has no installation step of its own. It serves and imports the files in
`static/data` exactly as the exporter writes them.

## Workflow

1. In the exporter, select this checkout's `static/data` as the **Output Files Directory**
   (`--out` on the command line).
2. Run the normal **Import and Export** action. From the command line:

   ```powershell
   dotnet run --project .\D2RMultiExport.Console -- export `
     --mod-data "..\d2r-reimagined-mod" --casc-data "<path-to-CascView-extraction>" `
     --out "..\d2r-reimagined-website\static\data"
   ```

3. Review, commit and push the website changes, keeping `static/data` changes in their own
   commit, separate from code changes.

There is no separate website install step or setting. A normal export overwrites files with
matching paths, creates new files and leaves every other existing file untouched, so check
`git status` for obsolete files a previous export left behind.

**Destructive export** (the exporter's "Destructive export — replace all existing destination
contents" checkbox, or `--destructive`) is optional and off by default. It generates the run in a
hidden `.d2r-export-new-*` directory inside `static/data` and, only after a run without errors,
replaces all previous contents of `static/data`, including obsolete files. A failed or aborted
run keeps the previous contents. A destructive run killed mid-replacement can leave hidden
`.d2r-export-new-*` or `.d2r-export-old-*` directories behind; do not commit them. The next
destructive export removes them. For the details, see "Export modes" in the exporter's
`README.md`.

## Retired migration scripts

`data:restore-removed` and `data:remap-recipes` were removed. They patched earlier exports made
from incomplete source submissions, and the merged source export supersedes them. Every cube
recipe now ships a stable exporter `Id`. `src/lib/data/cube-recipe-aliases.json` stays as frozen
compatibility data, so links saved with old recipe numbers still resolve through
`src/lib/cube-recipe-ids.ts`. Do not edit exported recipe JSON or recipe identities to keep
links working.
